## 0. Goal

Complete the human decision loop in the Control Center for the two surfaces that are currently read-only:

1. **Approvals** — inline Approve / Reject with live status, reusing the exact `approvals.approve` /
   `approvals.reject` path that MCP uses (deferred ops applied identically).
2. **Tasks** — create (already UI-backed), edit, and delete, restricted to the fields the existing task
   store actually supports, preserving `task.agent` / run-assignment semantics.

Everything else in Proposal 1 (automation, policy) is out of scope for this slice.

## 2. Slices

Two independently shippable slices. **Slice A** is self-contained (approvals). **Slice B** (tasks) is
independent of Slice A — order matters only for review cadence, not dependencies.

### Slice A — Approvals resolve (Approve / Reject)

**Command layer** (`openWorkforceControlCenter.ts`)
- Add `WORKFORCE_RESOLVE_APPROVAL` branch next to `WORKFORCE_DECIDE_FINDING` (`:673`).
  - Payload: `{ approvalId: string, decision: 'approved' | 'rejected', actorId?: string }` (actor optional —
    mirror findings `validatorId` optionality; `resolve` internally yields ok when actor is undefined).
  - Call `approvalId, decision` → `approvals.approve(id, actorId)` / `approvals.reject(id, actorId)` per decision.
  - Success: `postResponse(requestId, { resolved: true, approvalId, decision, approval: approvalDtoById(id) })`
    then `pushSnapshot` (keeps approvals + counts sync). Error: `postResponse(..., 'No pending approval found for <id>')`
    or the thrown message.
- Add `approvalDtoById(id)` helper beside `approvalDtos()` (`.find` over the same dto mapping).

**Webview** (`WorkforceControlCenter.tsx`)
- Approvals card (`:1458-1474`): for `status === "pending"` render **Approve** / **Reject** buttons.
  - Deliver: `postRequest("WORKFORCE_RESOLVE_APPROVAL", { approvalId, decision, actorId })`.
  - Guard double-submit (disable both buttons while in-flight); on `resolved` response, patch the approval
    in local `approvals` state (status/resolvedAt/decisionBy) and clear error; render error line on failure.
  - Keep the empty-state and decided-card rendering unchanged.

**Tests** (`test/smoke/workforceControlCenter.test.ts`)
- New describe `'v0.12 Proposal 1 — approvals resolve (Slice A)'`:
  1. Config-change gate is manual → an approval is pending → Approve via the webview message
     (`WORKFORCE_RESOLVE_APPROVAL`) → status flips to `approved`, `resolvedAt` set, deferred op applied.
  2. Reject path on a `task-assignment` approval → status `rejected`, task assignment NOT applied.
  3. Bad id / double-resolve → error payload, no crash, snapshot unchanged.

### Slice B — Tasks edit & delete

**Command layer** (`openWorkforceControlCenter.ts`)
- Add `WORKFORCE_UPDATE_TASK`: payload `{ taskId: string, updates: { title?, status?, priority?, agent? } }` →
  `taskService.updateTask(taskId, updates)`; success `postResponse(requestId, { updated: true, taskId, task: taskDtoById(id) })`
  then `pushSnapshot`. Guard: task must exist; update keys filtered to the DTO-supported set
  (`title|status|priority|agent`) to avoid writing unsupported `Task` fields.
- Add `WORKFORCE_DELETE_TASK`: payload `{ taskId: string }` → `taskService.deleteTask(taskId)`;
  success `{ deleted: true, taskId }` + `pushSnapshot`.
- Add `taskDtoById(id)` helper beside `taskDtos()`.
- Do **not** touch `WORKFORCE_CREATE_TASK` (already wired).

**Webview** (`WorkforceControlCenter.tsx`)
- Tasks list (`:1792-1811`): each card gains an **Edit** and **Delete** action.
  - Edit: inline editable title, priority, status (existing task statuses: `backlog|todo|in-progress|review|done`),
    agent (reuse employee list + openEmployee link). Save → `WORKFORCE_UPDATE_TASK`.
  - Delete: confirm then `WORKFORCE_DELETE_TASK`; remove from local `tasks` state on `deleted` response.
  - Keep the Create Task tab / `handleCreateTask` flow as-is.
- Do not rework the DTO subset; display/edit scope stays identical to `taskDtos()`.

**Tests** (`test/smoke/workforceControlCenter.test.ts`)
- New describe `'v0.12 Proposal 1 — tasks CRUD (Slice B)'`:
  1. Update title/priority/status/agent via `WORKFORCE_UPDATE_TASK` → `taskDtos()` reflects the new values
     and persists across `loadTasks()`.
  2. Unknown task id → error payload; unsupported update keys are ignored (only DTO set written).
  3. Delete via `WORKFORCE_DELETE_TASK` → gone from `SET_WORKFORCE_TASKS` and `loadTasks()`.

## 4. Risks / guardrails

- **Deferred ops must stay untouched:** Approve/Reject must call `approvals.approve/reject` *exactly* as the
  MCP handlers do — no re-implementation of the side effect. Failure string parity with
  `src/mcp/handlers/approvals.ts:47`.
- **Message boundary is stringly-typed:** a typo silently no-ops; each added command gets a smoke test around
  the real message flow, not just the service.
- **Task write scope:** restrict update keys to the DTO subset; never write arbitrary `Partial<Task>`
  (epic/backlog/status machine transitions stay internal).
- **Run-assignment invariant:** reassigning `agent` while a run is queued must not orphan `run.agentId`;
  Slice B keeps edit to metadata only — no run/task state machine changes.
- **No policy change:** Slice A does not touch gate modes, `setGate`, or permission defaults. `approval:review`
  enforcement remains the same as v0.11.
