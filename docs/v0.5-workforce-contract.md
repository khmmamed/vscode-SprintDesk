# v0.5 — Workforce Semantics Contract

Deterministic, policy-gated mapping of **Employee → Skills → Tools → Permissions → Task capability**
so v0.6's queue/scheduler/worker can select an agent for a task **without an LLM**.

Boundaries: v0.5 ships the *matching contract and lifecycle gates* only. The queue, scheduler,
worker runtime, and autonomous execution remain explicitly **out of scope** (v0.6).

---

## 1. Data model

### Skill catalog — `.SprintDesk/workforce/skills.yml`

```yaml
skills:
  - id: skill_debugging
    name: debugging
    category: engineering
    description: Root-cause and fix defects
    aliases: [bug, bugfix]
```

- `Skill{ id, name, category?, description?, aliases?[] }`.
- Matching is **case-insensitive on `name` and `aliases`**.
- A default catalog (8 skills) is seeded on first use (`SkillStore.seedDefaultSkills`).
- The default **task-type → required skills** mapping lives in `SkillStore.DEFAULT_TYPE_SKILLS`:

| task.type | required skills |
|---|---|
| `bug` | `debugging` |
| `doc` | `documentation` |
| `test` | `testing` |
| `feature` | `typescript, vscode-extension, apis` |
| `chore` | `planning` |

A task may override this with `Task.requiredSkills?: string[]` (additive, optional).

### Employee skills — `.SprintDesk/workforce/employees.yml`

```yaml
employees:
  - id: emp_spike
    name: Spike
    role: agent
    skills:            # certified skills (explicit)
      - name: typescript
        level: 3       # optional 1 | 2 | 3
    capabilities:      # legacy free-text, matched as level 1 (display alias kept)
      - vscode-extension
    teamRole: agent    # RBAC role: lead | developer | reviewer | observer | agent | human
    agentConfig:       # identity unification: copied from team.yml on syncWorkforceFromTeam
      tool: opencode
```

- `EmployeeSkill{ name, level?: 1|2|3 }` (additive, optional).
- `Employee.capabilities` remains as a free-text **display alias**; each entry is matched into the
  effective skill set at level 1 unless already certified.
- Effective skill set = certified skills ∪ capabilities, deduplicated, levels take the max.

### RBAC policy — `.SprintDesk/workforce/policy.yml`

```yaml
policy:
  roles:
    lead:      [task:assign, task:claim, run:create, run:cancel]
    developer: [task:claim, run:create]
    reviewer:  [task:assign, task:claim]
    observer:  []
    agent:     [run:create, task:claim]
    human:     [task:assign, task:claim]
  overrides:
    - employeeId: emp_spike
      deny: [run:cancel]
      allow: []   # allow is additive; deny removes a permission
```

- Effective role = `Employee.teamRole`, falling back to `agent`/`developer` from `Employee.role`.
- Effective permissions = role matrix ∪ `overrides[employeeId].allow` − `overrides[employeeId].deny`.
- If no policy file exists, `DEFAULT_POLICY` applies (same matrix).

## 2. Determinism contract

`capabilityService.rankEmployees(task, opts)` ranks qualified employees strictly by the following
order. Every tie is broken to the next key — **the result is fully deterministic**:

1. **Skill coverage** (matched / required) — descending. Only `coverage > 0` candidates enter
   the ranking; full-coverage (`qualifies`) is the default requirement unless `includePartial`.
2. **Concurrent load** (`run` records with status `queued`/`running` for that agent) — ascending.
3. **Status** — `idle` before `busy` (offline never ranked, cannot take work).
4. **Name** — ascending (`localeCompare`-free, plain `<`).
5. **id** — ascending (final tie-break).

## 3. Lifecycle gates

Permission enforcement is **only** on the three lifecycle gates; everything else is unchanged:

| Gate | Tool | Permission checked on | Refused when |
|---|---|---|---|
| Assignment | `sprintdesk_tasksAssign` | the assignee (`task:claim`) | assignee lacks `task:claim` |
| Claim | `sprintdesk_tasksClaim` | claimant (`task:claim`) | claimant lacks `task:claim` |
| Run start | `sprintdesk_runsCreate` | the acting agent (`run:create`) | agent lacks `run:create` |

- Resolved workers that are **not** workforce employees (legacy `team.yml` agents) have no policy
  record and are allowed (backwards compatible).
- `runsCreate` still refuses offline agents.
- Every recommendation is recorded in the audit trail (`action: recommendEmployees`,
  targetType `task`, full ranking). Read-only analyses use `rankEmployees` directly (no audit write).

## 4. New MCP tools (40 → 44)

| Tool | Purpose |
|---|---|
| `sprintdesk_skillsList` | Skill catalog (+ aliases) |
| `sprintdesk_skillsUpsert` | Add/update a skill |
| `sprintdesk_policyGet` | Permissions for a role or employee |
| `sprintdesk_recommendEmployees` | Deterministic ranked candidates for a task or type |

## 5. UI / CLI hooks (minimal)

- `SprintDesk: Add Employee` — skills picked from the catalog (multi-select) instead of free text.
- Workforce tree tooltip — certified skills with levels, capabilities, and effective permissions.
- `SprintDesk: Recommend Assignee` — inline action on tasks; ranks candidates and assigns on pick.
- `npm run standup` — "Matching Readiness" section (catalog size, certified-skill coverage,
  fully/partially/uncovered open tasks, aggregate skill gaps).

## 6. Non-goals (v0.6+)

- Queue/Scheduler/Worker runtime, autonomous execution, task → run routing.
- Permission enforcement beyond the three gates (e.g., on create/update/delete).
- Webview planning UI (a `sprintdesk.recommendAssignee` picker is the extent of the UI).
- `src/entry.ts` headless-halt cleanup (deferred runtime work).
