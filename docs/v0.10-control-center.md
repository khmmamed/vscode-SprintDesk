# v0.10 — Workforce Control Center (Slice 1)

Status: **in development** (version stays `0.9.0` until release)

Slice 1 makes the workforce runtime **visible and operable from VS Code** through a dedicated Control
Center webview plus a 7-section Workforce tree. It is the first complete user-facing flow:

```text
Employee → Create Task → Create & Run → Queue → Worker → Result
```

Scope is deliberately narrow: no auto-polling (queue stays manual), no workflow/schedule/approval UI yet,
no provider-configuration screen. The legacy project-management React screens are untouched.

## Control Center webview

`SprintDesk: Open Workforce Control Center` (`sprintdesk.openWorkforce`) opens a webview panel rendered as
the existing single React bundle with `?view=workforce` (`src/webview/workforce/WorkforceControlCenter.tsx`).

Tabs:

- **Employees** — agent employees with status/provider/tool chips and a **Create Task** action.
- **Create Task** — title, type, priority, backlog, agent, run mode (`ollama | headless | terminal | noop`),
  **Create & Run** button with live progress.
- **Runs** — live cards: task title, agent, status, started time, `Findings: N / Errors: N`, expandable raw
  output, cancel for queued/running.
- **Approvals / Schedules / Workflows / Activity** — counted placeholders (surfaces land in later slices).

### Webview ↔ extension protocol (`src/commands/workforce/openWorkforceControlCenter.ts`)

| Webview → Extension | Extension → Webview |
| --- | --- |
| `WORKFORCE_INIT` | `SET_WORKFORCE_INIT {section, focusAgentId}`, `SET_WORKFORCE_OVERVIEW`, `SET_WORKFORCE_COUNTS`, `SET_WORKFORCE_EMPLOYEES`, `SET_WORKFORCE_TASKS`, `SET_WORKFORCE_RUNS` |
| `WORKFORCE_CREATE_TASK {title,type,priority,backlog,agentId,runMode}` | `RUN_UPDATED {run}` per transition, `WORKFORCE_RESPONSE {runId,taskId,ran,approvalRequired}` |
| `WORKFORCE_CANCEL_RUN {runId}` | `RUN_UPDATED {run}` |
| `WORKFORCE_REFRESH` / `WORKFORCE_GET_RUNS` | snapshot / runs list |

The handler **composes existing services only** — `taskService.createTask` → `queueService.createRun` →
`queueService.startRun` → `worker.executeRun`. `QueueService` remains the sole authority for run state
transitions; the webview command never mutates run state itself.

### Slice 1 hardening

- Command-layer errors (offline agent, no agent assigned, missing `run:create`) are posted back as
  `WORKFORCE_RESPONSE { error }` — the webview never hangs on a rejected handler.
- `run:cancel` is granted to the default `agent` role (additive), so the Control Center / tree cancel
  works without a lead. Workspaces that already persist a `policy.yml` with explicit `roles` keep their file
  as the authority (merge is wholesale on `roles`, as before).
- The Workforce tree refreshes after every run transition driven by the Control Center (queued → running →
  completed/failed/cancelled), so the Runs section tracks status live.

## Workforce tree (7 sections)

`src/providers/workforce/WorkforceTreeDataProvider.ts` now renders nav rows:

```text
WORKFORCE
├── Employees (N)
├── Tasks (N)         → agent-assigned tasks
├── Runs (N running)  → recent runs, status icons
├── Approvals (N)     → opens Control Center
├── Schedules (N)     → opens Control Center
├── Workflows (N)     → opens Control Center
└── Activity          → opens Control Center
```

`employeeAgent` / `employee` / `workforceTeam` contextValues are preserved so all existing commands
(assign to team, set availability, remove, set lead) keep working. New commands:

- `sprintdesk.openWorkforce` — open the Control Center (nav rows + command palette + view/title).
- `sprintdesk.createTaskForEmployee` — from an agent tree row, opens Create Task pre-selected for that agent.
- `sprintdesk.cancelRun` — from a queued/running run row (queued/running guards enforced by `cancelRun`).

## Backend changes (additive, non-breaking)

### `queueService.createRun(taskId, agentId?, opts?)`

New single source of truth for run creation:

1. resolve task (by id or code); *throw* `Task not found` / `No agent assigned …` / gate error / offline error.
2. `getStores().runs.add(run)` + task `runId/attempts/agent` tagging + audit.
3. returns the queued `Run`.

`src/mcp/handlers/runs.ts` `sprintdesk_runsCreate` now calls it (identical error strings, `actor: 'mcp'`).

### Ollama worker runtime

`WorkerMode = 'headless' | 'terminal' | 'noop' | 'ollama'`. `worker.getWorkerRuntime('ollama')` returns
`createOllamaWorker()` (`src/services/workforce/worker/ollamaWorker.ts`):

- Resolves `employee.modelProfile` (fallback: `agentConfig.model` with default Ollama base URL).
- Builds a system/user prompt from the employee, task title, and task-file contents; calls the provider
  through `llm/registry` → `profileToRequest`.
- Complete output → `status: completed, output`; provider/transport errors → `failed` + `spawn-error`;
  missing model → `invalid-config`. Retryability is governed by the existing `requeueRun` classification rules.

### Structured run summaries

`Run.summary?: { findings: number; errors: number }` computed in `finishRun` via
`summarizeRunOutput(output, error, failed)`:

- explicit `Findings:` / `Errors:` sections (bullet counting), `Errors: 0` / `- 0` → zero;
- fallback: count bullet lines as findings, error-pattern lines as errors;
- failed runs with an error string count at least one error.

Stored by `finishRun`; surfaced by the webview and available to MCP runs list/get. `RunSummary`-aware fields
are YAML-serialized as-is (stores are schema-free), so `summary` round-trips.

## Manual demo (no local Ollama needed for the pipeline)

1. Add an agent employee (**SprintDesk → Workforce → Add Employee**, role *Agent*).
2. Optionally give it a model profile (`modelProfile: { provider: 'ollama', model: '…', baseUrl: 'http://localhost:11434' }`
   in `.SprintDesk/workforce/employees.yml`).
3. Tree: `Employees → <agent> → Create Task & Run` (or the Control Center Create Task tab).
4. Pick run mode **Noop** to verify the pipeline without external tools, then **Ollama** when a local model is available.
5. Watch **Runs** update live: Completed → `Findings: N / Errors: N` → raw output.
