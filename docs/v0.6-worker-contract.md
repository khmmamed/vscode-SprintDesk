# v0.6 — Queue, Scheduler & Worker Contract

Deterministic queue + execution boundary built on the v0.5 workforce semantics.
Maps `Run → Employee → WorkerRuntime → finishRun` without an LLM in the scheduling
path, and keeps every run state transition in one place.

---

## 1. Data model

### Queue settings — `.SprintDesk/workforce/queue.yml`

```yaml
queue:
  enabled: true
  maxConcurrentRuns: 2
  autoAssignUnassigned: false
  workerMode: headless   # headless | terminal | noop
  pollIntervalMs: 60000
```

- `QueueSettingsStore.getSettings()` / `saveSettings(partial)`.
- `workerMode` selects the default `WorkerRuntime`; `noop` is the deterministic option.

### Run records — `.SprintDesk/data/runs.yml`

```yaml
runs:
  - id: run_1789...
    taskId: <uuid>
    agentId: emp_<ts>_<uuid8>
    status: queued | running | completed | failed | cancelled
    attempts: 1
    createdAt: ...
    updatedAt: ...
    startedAt?: ...
    finishedAt?: ...
    result?: string
    error?: string
```

Created via `sprintdesk_runsCreate` (gate `run:create`, offline check) or directly as queued records.

## 2. Scheduler pass — `queueService.processQueue`

Pure claim phase over queued runs; **never executes** agents.

Order (deterministic): `createdAt asc → attempts asc → id asc`.

Per queued run, in order:

1. task exists? else `task-not-found`
2. task not `done`/`cancelled`? else `task-closed`
3. employee exists? else `employee-not-found`
4. employee not `offline`? else `employee-offline`
5. employee has `run:create`? else `no-permission`
6. employee not already running/claimed this pass? else `concurrency-limit`
7. global budget `available = min(limit, maxConcurrentRuns) - runningRuns.length` not exhausted? else `concurrency-limit`

A claim binds run + task + employee. Non-dry passes call `startRun` per claim; `dryRun`
(also `sprintdesk_queueGet`) previews `claims` + `skipped` without writing.

### Single transition path

| fn | effect | audit |
|---|---|---|
| `startRun(runId)` | run → running, employee → busy, task `workStatus` → in-progress | `run.start` |
| `finishRun(runId, {status: completed|failed, result?, error?})` | run → final, employee → idle, task `workStatus` → done/blocked | `run.finish` |
| `cancelRun(runId, actorId?)` | run → cancelled (employee → idle if it was running); gate `run:cancel` | `run.cancel` |

Every state change flows through these three; handlers and workers never mutate run
status directly.

## 3. Worker runtime — `src/services/workforce/worker/`

```ts
interface WorkerRuntime {
  mode: WorkerMode;                        // headless | terminal | noop
  run(request: WorkerRequest): Promise<WorkerResult>;
}
interface WorkerRequest {
  run: Run; task: Task; employee: Employee; agentConfig: AgentConfig; workspaceRoot: string; timeoutMs?;
}
interface WorkerResult { status: 'completed' | 'failed'; output?; error?; }
```

- `getWorkerRuntime(mode?)` — default from `queue.workerMode`.
- `executeRun(runId, mode?)` — requires run `running` + `employee.agentConfig`, runs the runtime,
  then delegates the final transition to `finishRun(runId, …)`. Returns `undefined` on precondition failure.
- `runQueuePass({mode?, limit?})` — orchestrates `processQueue(non-dry)` + `executeRun` per started run.
  Shared by the `sprintdesk.queueProcess` MCP tool, the `SprintDesk: Process Queue` command, and the CLI worker.

### Modes

- **headless** — `child_process.spawn(command, args, { cwd: workspaceRoot, shell: false })`;
  falls back to `shell: true` on win32 `ENOENT` so quoted multi-arg prompts are preserved.
- **terminal** — lazily `require('vscode')`, opens the integrated terminal.
- **noop** — deterministic: returns `completed` with `noop: <invocation>`; safe for tests/dry-runs.

### commandBuilder

`sanitizeBranchName`, `getRoleFilePath`, `loadAgentRole`, `buildAgentCommand` — extracted verbatim from
`agentRunner` and shared, preserving legacy agent-runner behavior.

## 4. MCP tools (44 → 49)

| tool | gate | behavior |
|---|---|---|
| `sprintdesk_queueGet` | read-only | settings, capacity, queued/running runs, next claims + skip reasons (dry-run) |
| `sprintdesk_queueProcess` | `run:create` (actor) | one synchronous claim+start pass, then `executeRun` per started run via worker boundary |
| `sprintdesk_runsCancel` | `run:cancel` | delegates to `queueService.cancelRun`; no handler-side transition |
| `sprintdesk_runsUpdate` | `run:update` + caller must be the run's agent | validates run `running` and `completed|failed`, delegates to `queueService.finishRun` |
| `sprintdesk_tasksAutoAssign` | none (explicit only) | deterministic `rankEmployees` → top eligible → writes only `task.agent`, audits `auto-assign`; never called automatically |

## 5. Invariants

- **Determinism:** the scheduling path uses no randomness or wall-clock ordering beyond `id`/`createdAt`.
- **No implicit assignment:** `queueProcess`/`processQueue` never write `task.agent`; assignment is explicit
  via `tasksAssign` / `tasksAutoAssign`.
- **Single write path:** runs mutate only through `startRun` / `finishRun` / `cancelRun`.
- **Canonical identity:** `task.agent` = employee id; legacy `task.assignee` remains read-only via
  `getTaskAssignee(task) => task.agent ?? task.assignee`.
- **Permission additions (v0.6):** `run:update` granted to `agent` and `lead`; `run:cancel` unchanged.
